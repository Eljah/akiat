Akiat — локальный редактор проблемных пар WAV/текст (Java Swing, JDK 11+)

Сборка и проверки: powershell -ExecutionPolicy Bypass -File desktop/build.ps1 -Test
Запуск: powershell -ExecutionPolicy Bypass -File desktop/start.ps1
Или: java -jar desktop/build/akiat-review-2.jar ПУТЬ_К_ОТЧЁТУ
Приложение без Maven/сетевых зависимостей. JAVA_HOME должен указывать на JDK 11+.
На текущей машине используется D:\Java\jdk-11.0.15; java из PATH может оказаться Java 8.

Слева — проблемные фрагменты. Поиск по исходнику, ID и тексту.
Сверху — неизменяемый исходный текст; ниже — поле для исправлений.
Выберите слово в тексте/таблице/на шкале. Двойной щелчок или «Слово ±0,5 с»
воспроизводит его приблизительную окрестность. Ctrl+Space — воспроизведение/пауза.
Щелчок по волне или ползунок — перемотка. Кнопки ±0,5 с помогают искать границу.
Перетащите подпись слова на шкале, задайте начало в таблице или нажмите
«Начало слова = курсор». Новая граница не должна пересекать соседние начала слов.
Красная подсветка — исходные замечания морфологии, жёлтая — выбранное слово.

В имеющихся labels JSON метки start/end относятся ко всему фрагменту исходного MP3.
Индивидуальных меток начала слов нет. Начальные позиции в редакторе — ОЦЕНКА:
длина слова распределяется по активным 25-миллисекундным участкам звука.
Тишина отсекается по амплитуде; музыка, шум и темп речи могут сильно сместить оценку.
kind=approximate — оценка; manual — уточнено человеком; imported — внешний источник.
Импорт не означает гарантированно точное выравнивание.
После изменения текста позиции пересчитываются, старые ручные метки сбрасываются:
сначала исправляйте слова, затем при необходимости уточняйте время.
После изменения текста старые морфологические метки не переносятся на другие слова.

Импорт временных меток из UTF-8 JSON:
{"uid":"ID_ФРАГМЕНТА","text":"Точный текущий текст","words":[
  {"word":"Первое","start":0.2,"end":0.8},
  {"word":"слово","start":0.9,"end":1.4}
]}
Время относительно начала WAV, в секундах; uid, текст и все слова должны совпадать.
Для получения акустически уточнённых меток нужен отдельный forced-alignment этап
с подходящей татарской моделью либо новое распознавание с word timestamps.
Этот редактор не запускает такие модели и не выдаёт приблизительные метки за точные.

Ctrl+S/«Сохранить черновик» и «Проверено»/«Исключить» пишут отдельные JSON в
ПАПКА_ОТЧЁТА/desktop_edits/. Текст, статус и временные метки восстанавливаются при открытии.
Исходные WAV, labels, metadata.csv и текущий процесс обучения не меняются.
Сохраняйте папку отчёта вместе с корпусом: ссылки WAV относительные.
Исправления ещё нужно отдельно собрать в новый metadata.csv и повторно обработать
для следующего запуска обучения. Автоматического применения к текущему обучению нет.
Piper использует аудио и полный текст фрагмента; метки слов ему напрямую не нужны.
Правильная расшифровка и отсутствие обрезанных слов важнее для этого обучения.

ОБРЕЗКА НАЧАЛА И КОНЦА
1. Поставьте курсор после начальной музыки и нажмите «Начало = курсор».
2. При необходимости поставьте курсор перед лишним концом и нажмите «Конец = курсор».
   Можно ввести обе границы в секундах и нажать «Применить границы».
3. Серым затемнены удаляемые части. ▶ воспроизводит только оставшийся диапазон.
   Ползунок по-прежнему показывает время относительно полного исходного WAV.
4. Исправьте текст, если обрезали произнесённые слова. Текст автоматически не удаляется.
5. «Сохранить черновик» / «Проверено» сохраняет отдельный WAV в desktop_edits/wav,
   исправленный TXT в desktop_edits/txt и описание в desktop_edits/UID.json.
   JSON содержит путь audio к выбранной версии WAV, corrected_text, trim_start/end,
   исходные слова words и words_for_saved_audio с временем от начала обрезанного WAV.
6. «Сброс обрезки» возвращает полный исходник; сохраните для отмены обрезки в правках.
   Прежние копии WAV остаются на диске. Оригиналы никогда не перезаписываются.

Обрезка производится по целым PCM-кадрам без перекодирования. Минимум 0,05 секунды.
При изменении границ позиции слов пересчитываются приблизительно внутри оставленного
участка; ручные метки следует выставлять после обрезки и исправления текста.
Старые сохранения без полей trim_start/end также поддерживаются.
