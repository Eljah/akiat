# Codex → MCP → озвучка → RSS: пользовательский процесс

**Основная архитектура:** Codex анализирует русские литературные произведения и пишет полный оригинальный татарский текст. Java не вызывает OpenAI для литературной работы. Java занимается хранением, очередью TTS, проверками и RSS.

## MCP-tools on `/mcp`

| Tool | Когда вызывать | Результат |
|---|---|---|
| `submit_tatar_story` | Codex закончил татарскую сказку | Новый `DRAFT` + `storyId`; уникальность по `clientId` |
| `get_akiat_story` | Нужен текст и текущий статус | Текст и статус |
| `approve_tatar_text` | После реальной редакторской вычитки | `LANGUAGE_APPROVED` |
| `start_tatar_narration` | Готовы озвучивать | `TTS_QUEUED` + `taskId` |
| `get_tatar_narration_job` | Отслеживание фонового задания | Состояние задачи: QUEUED/CLAIMED/COMPLETED/FAILED |
| `approve_tatar_narration` | Человек прослушал MP3 | `READY` |
| `confirm_tatar_publication_rights` | Подтверждены права на текст, исполнение, фонограмму, голос | права отмечены |
| `publish_tatar_episode` | Только после прямого разрешения пользователя | `PUBLISHED`, выпуск в `/feed.xml` |

При публикации отправьте `confirmation="PUBLISH:<storyId>"` с конкретным идентификатором, после явного подтверждения выпуска пользователем.

## Присоединение Codex к локальному серверу

1. Запустите Spring Boot и Python TTS-worker. Серверу нужен `AKIAT_ADMIN_PASSWORD`; MCP использует `AKIAT_MCP_TOKEN`.
2. В терминале компьютера с Codex:

```bash
export AKIAT_MCP_TOKEN='long-secret'
codex mcp add akiat --url http://127.0.0.1:8080/mcp --bearer-token-env-var AKIAT_MCP_TOKEN
codex mcp list
```

3. Для доступа с другой машины используйте HTTPS и защищённый частный канал (VPN/SSH-туннель). **Не публикуйте `/mcp` в открытом интернете**.

## Пример обращения к Codex

> Найди современные русские авторские сказки за последние годы, выдели эмоциональные группы и конкретные проверяемые литературные референсы. Для одной ранее не охваченной эмоциональной группы придумай оригинальную татарскую сказку для 5–7 лет, не копируя сюжетов, персонажей и сцен. Покажи текст и происхождение эмоционального профиля. После моей вычитки отдай полный текст в MCP `akiat.submit_tatar_story`, получи ID и подготовь его к озвучке.

**Никакой дополнительный OpenAI API ключ Java-серверу для этого процесса не нужен**: написание и анализ идут внутри Codex. У самого Codex могут быть отдельные лимиты или расходы в зависимости от способа доступа.

## Asynchronous release flow

`submit` → `approve language` → `queue TTS` → worker claims / synthesizes / uploads → `approve audio` → `confirm rights` → `publish`.

Запрос `start_tatar_narration` НЕ запускает GPU в Java; он создаёт задание. Воркер обязан быть онлайн и настроен на правомерно используемый голос. При ошибках состояние и описание можно получить через статусы задач (или логи воркера).

`PUBLISHED` означает доступность в локальной RSS-ленте Java после размещения на публичном хосте; не означает, что Яндекс принял подкаст или Алиса нашла эпизод.

## Storage / production warnings

Пока используется H2/JPA и локальные медиафайлы; это MVP. Перед публичной эксплуатацией нужны PostgreSQL + миграции, S3/MinIO, контроль доступа, резервные копии и проверка реального RSS/MP3 на HTTPS. Текущая MFA/role-based авторизация на разных MCP-операциях не реализована: MCP bearer token даёт полномочия редактора, поэтому подтверждение пользователя до вызовов публикации крайне важно.
